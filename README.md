# Slabbed physical-cell rewrite

Fabric 1.21.1. Experimental implementation of the original Slabbed idea: blocks and decorations sit directly on slab surfaces.

Pieces occupy physical half-block cells. One-block pieces that cross a cell boundary store a fragment in each of the two intersected cells. Vanilla raycasts, reach and collision therefore use the visible position. Placement origins are permanent; see LAW.md.

Supported adapters: static building cubes, slabs, logs, glass, glazed terracotta, leaves, ordinary and soul torches, chains, lanterns, flower pots and carpets. Signs, hanging signs, beds, banners, skulls and supported workstations retain native placement and interactions at a fixed half-block position. Signs keep their text and editing; beds keep their native pair and sleep behavior. Crafting, smithing, cartography, loom, stonecutter and grindstone menus remain native.

Placement checks physical clearance before accepting a click. Native blocks retain their ordinary states, block entities, inventories, scheduled ticks and interactions at a remembered half-block position. Separate static pieces can occupy unused physical space in a native owner's cell without replacing its data. Normal grid-aligned building pieces remain vanilla blocks whenever they fit one cell.

The native adapters cover containers, paired doors and beds, wall attachments, rails and minecarts, switches, redstone components, scaffolding and supported plants. Native particles use the remembered position. Supplemental luminous pieces participate in normal light propagation and chunk relighting. Custom modded mechanics still require dedicated compatibility testing.

Pistons move complete static pieces atomically, preserve independent slabs and stationary native inventories, and reject a thirteenth pushed piece. Native slime and honey can carry touching static physical branches, retaining their native behavior and their separation from the other adhesive type. Blocked branches reject before movement; a mismatch between native and physical movement graphs restores the static pieces and refuses the move. The native head and native adhesive blocks animate; static physical pieces currently relocate immediately. Other mixed pushes into separately seated native objects, fluid simulation and migration from the earlier offset format remain outside this candidate.

This is a fresh-world candidate. It does not interpret the old offset attachment format. Existing saves require an explicit migration before upgrading.

Actions validates the server and the Indigo, Sodium, Sodium-with-Lithium, and rendering-optimizer subset clients on every rewrite push. The rendering subset adds the fixture versions of OBE and MoreCulling with their configuration libraries and relevant pack configuration. Piston probes check all six orientations, client base/head poses, warmed face caches, and emitted model heights after extension and retraction. The Lithium subset uses the hash-verified version from the current pack fixture and exercises actual ordinary and lowered piston cycles in fresh and reopened worlds. Complete-pack and comparison checks run when the exact pack source is available; otherwise they are explicitly skipped and the missing inputs are listed in the workflow summary. They are never reported as a compatibility pass. Local pack checks accept `SLABBED_FULL_PACK`; Actions can download the exact archive from the `SLABBED_FULL_PACK_URL` repository secret. Its SHA-256 must match the current fixture before staging, and the pack is never published with the production JAR.

Optional local diagnostics: recording starts off. Use **F8** to start or stop and **F9** to export; both bindings can be changed under Controls → Slabbed diagnostics. Alternatives are `/slabbeddebug start`, `/slabbeddebug stop`, and `/slabbeddebug report [description]`. Start recording, reproduce the issue, then export. Reports are ZIP files in `logs/slabbed-debug/`; the saved-report message opens that folder. Attach the ZIP when reporting a bug. Nothing is uploaded automatically.

A report includes a bounded recent action history, piston power and refusal decisions, nearby loaded blocks and stored heights, mod/resource-pack versions, renderer settings, and a screenshot when available. Review the screenshot before sharing because it can include visible UI. Integrated worlds include server decisions and a server snapshot; remote servers provide client evidence only. This recorder does not automatically identify every visual defect. Recording stops on disconnect; up to ten reports and one rolling crash-history checkpoint are retained locally.
